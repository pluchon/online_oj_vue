## 明确不做

- 多语言判题（C++ / Python）：每道题的 main 函数和代码模板都按 Java 写，支持多语言需要为每题维护多套，出题和 AI 生成用例也要跟着改，投入最大。
- 讨论区 / 评论：要连带做内容审核、通知、举报和 @，维护成本高。
- Rating 积分、全站排行榜、题单。
- 题目批量导入导出。
- 数据概览「最近竞赛」的 AI 分析（2026-09-27 取消：能说的结论在人数与通过率上一眼可见，深入分析又与赛后 AI 复盘 T-015 重叠）。

## 任务拆分

仓库：**后端**指 `../online_oj`，**B 端**指 `oj_fe_b`，**C 端**指 `oj_fe_c`。

| ID | 任务 | 依赖 | 验收标准 |
|---|---|---|---|
| T-015a | 赛后复盘后端：friend 统计学员这场的成绩与逐题情况（是否通过、提交次数、首次通过用时、最后结论、全场通过率），新表 `tb_exam_review` 存复盘；ai 新增复盘接口与提示词（逐题一句话点评 + 整体总结，只给思路不给代码，不透露隐藏用例）；首次打开时生成，提交结果变了再打开时重新生成 | 无 | 未结算或没有提交的竞赛返回明确错误码；统计数字与数据库一致；第二次打开直接读表不调 AI；提交结果变化后重新生成；只能看自己的复盘 |
| T-015b | 赛后复盘 C 端：「我的竞赛」已完赛且有提交的卡片，封面图右上角显示「赛后复盘」标签按钮，打开复盘弹窗（生成中边框流光） | T-015a | 只在符合条件的卡片上出现；弹窗显示成绩概览、逐题回顾与整体总结；加载、生成中、失败三种状态都有 |

**验收标准要能验证**：写「接口返回 200 且字段齐全」，不写「接口能用」。

## 分工原则

T-015 先做后端（T-015a）再做前端（T-015b）；AI 调用沿用 T-030 的结构化输出与提示词写法。同一个任务内先做后端再做前端。
