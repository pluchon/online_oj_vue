# DECISIONS

> 项目进行中定下的决策。**只追加，不改历史**——决策被推翻时新写一条，在旧条目标注「已被 D-00X 取代」。
> 这是为了让后来的 agent 知道「为什么是现在这样」，而不是重新推一遍、或者改回被否掉的方案。

## 格式

### D-00X · YYYY-MM-DD · 一句话标题

- **决策**：选了什么
- **否决了**：考虑过哪些别的方案
- **理由**：为什么
- **影响**：哪些任务 / 模块要跟着变
- **决策者**：用户 / `agent名`

### D-001 · 2026-09-24 · 下一阶段只补 OJ 的基础功能

- **决策**：做题目标签、题解、提交管理与重判、数据概览四块；AI 只再加一个功能（赛后复盘或弱项推荐二选一）。
- **否决了**：多语言判题、讨论区 / 评论、Rating 积分与全站排行榜、题单、题目批量导入导出。
- **理由**：用户希望项目不做复杂，但基础功能要齐全。AI 模块已经覆盖出题、帮建竞赛、辅导、语义检索、相似题和资料审核，缺的是传统 OJ 的基础功能。多语言判题要为每题维护多套 main 函数，出题和 AI 生成用例都要跟着改；讨论区要连带做审核、通知和举报，投入产出比都低。
- **影响**：PLAN.md 的 M1–M5。
- **决策者**：`claude-code` 提议，用户同意落档

### D-002 · 2026-09-24 · 标签由出题人维护，取代关键词推断

- **决策**：新建标签表和题目标签关联表，标签在 B 端维护；friend 删除 `resolveQuestionTags` 的关键词推断，能力雷达图改用真实标签统计。
- **否决了**：继续扩充关键词规则；让 AI 在查询时实时推断标签。
- **理由**：关键词推断出题人改不了，也不准；雷达图、相似题、AI 帮建竞赛的检索和后续的弱项推荐都需要准确的标签。AI 只在出题时建议标签，由出题人确认后保存。
- **影响**：T-001 ~ T-005，以及 T-015 中的弱项推荐。
- **决策者**：`claude-code` 提议，用户同意落档

### D-003 · 2026-09-25 · 新表主键用雪花 ID

- **决策**：标签表、题目标签关联表、题解表的主键都用雪花 ID。
- **否决了**：像 `tb_question_case` 那样用自增主键。
- **理由**：项目主键有意使用雪花 ID；题目表本身就是雪花 ID，关联表要存题目的雪花 ID，两边保持一致。
- **影响**：T-001、T-006。
- **决策者**：用户

### D-004 · 2026-09-25 · 标签功能不新增路由页面

- **决策**：M1 的标签功能全部放在现有页面里：B 端题目管理页用弹窗管理标签，题目抽屉里选标签，列表加一列；C 端题库筛选栏加标签和做题状态筛选，题目卡片和做题页显示标签。
- **否决了**：B 端单独做一个「标签管理」侧边栏页面。
- **理由**：标签只是题目的一个属性，数量不多，弹窗就够用；不新增页面也省去单独设计 UI。新控件照搬现有的难度分段和 `OjDialog` 样式。
- **影响**：T-002、T-004。
- **决策者**：用户
